# dsh-breaklimit 0.9.5 (内测版)

这一版是可靠性与数据安全的集中修复版：规则落点按原字节保真读写、并发冲突与输入错误清晰区分、升级与回退流程更稳健。0.9 系列用于内测，正式版计划为 1.0.0。补丁内容、提示词正文与词库替换语义与 0.9.4 保持一致。

## 规则与落点数据安全

- **非 UTF-8 编码原样保真**：彻底修复非 UTF-8（如 GBK、UTF-16 等旧文本编辑器产物）的 `AGENTS.md` / `CLAUDE.md` 在读写回写时被解码损坏的问题。落点与快照全程基于原始字节流处理，内容无变动时不触碰重写，非 UTF-8 落点不作自动收拢，原样保留。
- **读失败显式拦截报错**：落点、清单或正文文件存在但因权限或文件占用等原因读取失败时，激活、保存、取消激活一律立即停手并显式报错，杜绝因偶发读取失败误判为「文件不存在」而触发空清单整表覆盖，或将宿主文件误当成插件自建文件直接删除。
- **外部改动安全留存**：激活操作若需覆盖落点上的外部修改，系统会预先在 `landings/<target>.external-*.txt` 保存副本，并在操作结果中告知副本路径；切换落点留下的无归属快照同样遵循「先保留再替换」。撤销时严格依据写入记录判定归属，避免因单次同步失败将保存状态永久锁死在「已被改动」。
- **状态重建工具防自毁**：重建状态记录工具在无任何有效文件被采纳时直接拒绝写入；备份文件永不覆盖，脚本退出码如实反映执行结果。

## 提示词与恢复链路修复

- **字面段保真注入**：注入文件、激活规则与尾部内容作为字面段（literal segment）拼入最终提示词，内容中包含的 `{{cwd}}`、Vue 模板语法等不再触发宿主变量解析错误；宿主 Persona 的合法变量插值保持正常解析。
- **快照继承与收尾续做**：同落点切换沿用首次生成的基准快照；跨落点切换在新激活规则提交成功后才执行收尾。若过程失败或中断，保留 `cleanup` 意图供启动与后续操作继续处理。版本降级前，优先处理尚未完成的收尾任务。
- **并发事务锁与候选过滤**：状态重建与补丁事务共用文件锁，跳过回退备份等无效原文候选，防止并发操作导致状态踩踏。
- **词库与交互时序保护**：词库状态结果未知期间，暂停写入与预览，避免脏数据写入；规则编辑中新增的草稿在保存时予以完整保留；取消激活失败时明确显示「仍处于激活」，不报虚假成功；更新检查超时后立即释放代理隧道。

## 切档与执行层预算

- **执行层预算继承**：配置中声明的执行层预算（超时时间、输出上限、子代理深度等）在切档后不再被遗弃回落为内置默认值，与初始化装载期保持统一的取值来源。
- **切档三态明确归因**：切档结果明确划分为三态反馈——只有确定失败时才提示「未切换」；超时或断网等网络异常归为「结果未知」并自动重新读取核对；若重试读回依然失败，如实提示「未核对上」，彻底杜绝误报。

## 状态探测与前端交互

- **会话档位精准归因**：状态报告中的档位附带归因信息。未探测到实际会话时，状态徽章如实显示「档位未探测」，不再将部署默认档冒充为当前会话档位展示；宿主预设读取异常时自动降级为缺省值，不再导致整体状态接口抛出 HTTP 500 异常。
- **前端可靠性优化（八项修复）**：
  - 时序保护：状态加载引入时序校验，先发后到的过期响应不会覆盖界面的最新数据。
  - 精准删除：悬浮窗词条删除严格按词条身份（ID/Token）锚定，词库列表变动时不会误删临近项。
  - 动态词库上限：词库上限严格以下发配置值为准，后端调高限制后前端不再静默裁剪词条。
  - 未保存草稿确认：规则编辑器中存在未保存草稿时，离开或切换前增加确认提示。
  - 视口边界约束：浮窗位置坐标读回时自动限制在可视区域内，避免不同屏幕分辨率下浮窗跑出屏幕。
  - 防抖拦截：更新弹窗增加状态防抖，不再被迟到的轮询响应意外重新触发弹开。
  - 错误原因穿透：版本自动检查失败时穿透底层错误信息，如实向用户呈现具体失败原因。
  - 写入与预览互锁：词库状态不明确期间即时禁用操作入口，保障前端与后端状态严格一致。

## 命令行与工程守卫

- **严格参数与互斥校验**：命令行遇到未知参数（如拼写错误的 `--aply`）或多动作冲突组合（如 `--status --apply`）时显式报错并以退出码 2 终止，不再假成功或静默执行具有破坏性的操作；宿主根目录未配置时，`--status` 退出码为 2 并明确注明「预检被跳过 ≠ 通过」。
- **对账哈希归属校验**：哈希表采集前强制校验目标宿主 Git 提交归属，杜绝针对非目标代码树生成哈希表而导致对账校验产生「伪阳性正确」；文档数字守卫扩展覆盖至补丁声明层数字。

## 安装与升级

适用于已能正常运行的 DeepSeek Harness 源码版 **0.2.1-rc.2**（固定宿主提交为 `687f282e8625c6b8d11ff58211a90524be2e4317`）。需要 Git、pnpm 以及兼容的 Node.js（推荐 Node 24）。

**第一次安装？**

- 从 Release 附件下载 `dsh-breaklimit-0.9.5.zip`，解压到固定目录。
- 参考 [README 快速安装指南 (Windows PowerShell)](https://github.com/rumoii/dsh-breaklimit/blob/v0.9.5/README.md#快速安装windows-powershell) 完成环境准备：准备 Web profile、安装插件、运行环境预检并应用补丁。

**从 0.9.4 升级**

已经在用 0.9.4 的用户，保存本地修改后更新插件目录代码，重启宿主即可：

- 原有的 `DSH_HOME`、规则列表、自定义词库与恢复快照均会保留。
- 规则存储格式向后兼容（新字段为增量设计，旧记录读写不受影响），无需任何数据迁移操作。
- 更早版本的升级差异、回退与完整卸载步骤，请查阅 [安装与回退文档](https://github.com/rumoii/dsh-breaklimit/blob/v0.9.5/docs/install.md)。

## 使用边界与验收说明

**安全边界**：仅供受信任的本机 Web 环境使用。插件管理接口尚未接入宿主登录认证，切勿将端口直接暴露给不受信任的公网或局域网。在 Web 界面或命令行操作规则时，也请避免其他程序并发改写同一规则文件。

**验收状态**：已完成 Windows 平台源码版完整安装链路与核心接口层验收（规则链路、切档预算继承、并发冲突分流、状态归因），并经真实 Web 环境试用确认。
