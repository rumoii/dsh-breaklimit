# dsh-breaklimit 0.9.5 内测版

这一版是可靠性与数据安全的集中修复版：规则落点按原字节保真、并发冲突与输入错误终于可以区分、升级和回退更稳。0.9 系列用于内测，正式版计划为 1.0.0。补丁内容、提示词正文与词库替换语义与 0.9.4 一致。

## 提示词与恢复修复

- 注入文件、激活规则和尾部作为字面段进入最终提示词，`{{cwd}}`、Vue 模板等内容不再触发宿主变量解析错误；宿主 persona 的合法插值保持有效。
- 同落点切换沿用首次快照；跨落点在新激活提交后收尾，失败或中断保留 `cleanup` 意图供启动与后续操作续做。降级前先处理尚未完成的收尾。
- 重建状态与补丁事务共用文件锁，跳过回退备份等无效原文候选。
- 词库结果未知期间暂停写入与预览；规则保存保留新增草稿；取消失败时显示仍激活；更新检查超时后释放代理隧道。

## 规则与落点的数据安全

- 非 UTF-8（GBK、UTF-16 旧编辑器产物）的 `AGENTS.md` / `CLAUDE.md` 不再被解码写回毁掉：落点与快照按原字节读写，内容没变就不重写文件，非 UTF-8 的落点不自动收拢、原样保留。
- 「文件读不到」不再被当成「文件不存在」：落点、清单或正文存在但读不到时，激活、保存、取消激活一律停手报错，不再把读失败当成空清单整表替换或当成插件自建的文件删掉。
- 激活覆盖落点上的外部改动前会先存副本（`landings/<target>.external-*.txt`）并在结果里告知路径；切换落点留下的无归属快照同样先保留再替换。撤销时按写入记录判断归属，一次同步失败不再让保存永远停在「已被改动」。
- 重建状态记录的工具不再自毁：一个文件都没采纳时拒绝写入，备份永不覆盖，脚本退出码如实。

## 切档与执行层预算

- 配置里的执行层预算（超时、输出上限、子代理深度）在切档后不再被丢弃回落内置值，与装载期同一取值来源。
- 切档结果分三态：明确失败才说「没切」；超时或断网报「结果未知」并自动重新读取核对，连读回都失败时如实说「没核对上」，不再误报。

## 状态与界面

- 状态报告的档位带归因：没探测到会话时徽章显示「档位未探测」，不再把部署默认档当成会话档位展示；宿主预设读取失败降级为缺省，不再把整个状态接口打成 500。
- 前端可靠性八项：状态加载先发后到的旧响应不再覆盖新数据；浮窗删除按词条身份锚定，列表变化不误删；词库上限以下发值为准，后端调高上限后不再静默删词；规则编辑的未保存草稿离开前确认；浮窗位置读回即夹进视口；更新弹窗不再被迟到响应重新弹开；自动检查失败如实显示原因。

## 命令行与维护工具

- 未知参数（如拼错的 `--aply`）和多动作组合（如 `--status --apply`）显式报错并以退出码 2 结束，不再假成功或静默选中破坏性动作；宿主根未配置时 `--status` 退出 2 并注明「预检被跳过 ≠ 通过」。
- 哈希表采集前校验宿主提交归属，不对着别的树生成会被对账当成正确的哈希表；文档数字守卫覆盖到补丁声明层数字。

## 安装与升级

适用于已能运行的 DeepSeek Harness **源码版 0.2.1-rc.2**，固定宿主提交为 `687f282e8625c6b8d11ff58211a90524be2e4317`。需要 Git、pnpm 和兼容的 Node.js，推荐 Node 24。

**第一次安装？** 下载附件 `dsh-breaklimit-0.9.5.zip`，解压到固定目录，再按 [README 安装指南](https://github.com/rumoii/dsh-breaklimit/blob/v0.9.5/README.md#快速安装windows-powershell) 准备 Web profile、安装插件、运行检查并应用补丁。

已经在用 0.9.4 的用户，保存本地修改后更新插件目录，再重启宿主即可。保留原有的 `DSH_HOME`、规则、词库与恢复快照；规则存储格式向后兼容（新字段为加法，旧记录读写不受影响），无需迁移。更早版本的升级差异，以及回退和卸载步骤，见 [安装说明](https://github.com/rumoii/dsh-breaklimit/blob/v0.9.5/docs/install.md)。

## 使用范围

仅用于受信任的本机 Web 环境。插件管理接口尚未接入宿主登录认证，请勿将端口暴露给不受信任的网络。操作规则时，也请避免其他程序同时改写规则文件。

本次已完成 Windows 源码版安装与接口层验收（规则链路、切档预算、并发冲突分流、状态归因）；浏览器交互细项、断电持久性与多进程真实争用尚未验收。桌面版、其他宿主版本、Ubuntu 实际安装、完整模型与沙箱场景尚未验收。
