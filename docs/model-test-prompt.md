## 模型对照用例

先列出具体输入与可观察的通过条件，再开始调用；通用回归加项目已有代表性用例即可，不建设评测平台。

1. **身份与表达约定**：给定固定的称呼、语言、格式与输出约定，检查普通任务中的遵循情况。记录实际响应，不仅询问模型自称是什么。
2. **规则注入**：同一任务分别激活两条具有明确输出差异的规则，检查切换后是否采用当前规则；取消成功后检查该规则停止生效。外部修改导致取消被保留时，应该仍然生效且界面如实说明。
3. **工具完成能力**：在临时工作区完成一个可检查结果的多步骤文件任务，确认实际工具调用、文件产物和错误恢复，避免仅看口头承诺。两档模式分别记录。
4. **词库实际作用**：固定词表与输入，检查发送给模型的文本及实际命中记录；本地预览不能当作真实会话命中。替换语义仍是区分大小写、精确字面、长词优先、按顺序依次替换。
5. **模板正文**：注入文件和规则分别包含 `{{cwd}}`、`{{model}}`、`{{ count }}`、JSON 与代码块。修复后应能启动请求，用户正文原样保留；宿主 persona 的合法变量正常解析。旧版无法启动的结果单列为“已修复阻断”，不能混入一般模型响应质量统计。
6. **代表性历史用例**：优先使用用户已有、获准测试且有明确预期的实际用例。没有现成样本时，先给用户一份短样本清单确认，不能把通用工具测试等同于全部破限效果。

普通无模板用例先确认最终提示词相同。相同输入出现响应差异时，针对该用例成对复测，区分偶发波动和可重复退化；不要因为单次更长、更顺从或自称无限制就判定质量提高。
